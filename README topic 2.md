Prompt Engineering Support AssistantProject OverviewThe Prompt Engineering Support Assistant demonstrates a multi-stage customer support prompting architecture built around the authoritative FlexTime Support Policy Manual. The system implements policy-grounded response generation, sentiment-aware empathy modeling, automated self-verification, structured human escalation, and CRM summarization to deliver safe, consistent, and audit-compliant support interactions.Project ObjectivesBuild a Policy-Grounded Assistant: Ground every response strictly in documented corporate policy to eliminate hallucinations and unauthorized commitments.Classify Intent and Sentiment: Accurately categorize customer queries and emotional states to determine the correct response path.Generate Empathetic Responses: Apply the CARE framework to craft concise, non-defensive, and validating customer replies under 100 words.Verify Responses Before Delivery: Audit drafted responses against financial limits, tone guidelines, and privacy restrictions.Escalate Breaches Automatically: Generate structured handover tickets when customer requests exceed frontline authority limits.Produce Structured CRM Summaries: Archive session telemetry into consistent Markdown tables ready for CRM integration.Demonstrate Prompt Engineering Workflows: Showcase a modular, sequential prompt-chain pipeline designed for enterprise customer support operations.Prompting ArchitectureThe architecture consists of five sequential stages:Stage 1 — Intent Classifier: Categorizes inbound customer queries into predefined operational buckets (Billing, Technical Support, Account Management, General Inquiry, Urgent Escalation) and assesses sentiment (Angry, Frustrated, Neutral, Satisfied).Stage 2 — CARE Responder: Synthesizes the classified category, sentiment, and policy manual to draft a personalized, empathetic response under 100 words.Stage 3 — Self-Verification / Reflection: Audits drafted replies against refund thresholds, privacy guardrails, and tone requirements, rewriting flagged responses prior to delivery.Stage 4 — Escalation Ticket: Compiles a standardized human handover ticket (=== TICKET SUMMARY ===) when an issue surpasses frontline authority.Stage 5 — Conversation Summarizer: Converts session logs into a 6-field structured Markdown table for permanent CRM archiving.Policy RulesAll prompts operate under the FlexTime Support Policy Manual as the sole source of truth:Operating Hours: Monday to Friday, 9:00 AM to 5:00 PM EST.Frontline Refund Limit: Agents can issue refunds up to a maximum of $20 without managerial approval.Dispute Escalation: Any billing dispute or refund request exceeding $20 must be escalated.Email Modifications: Profile email changes require verification of the customer's current Account ID and billing ZIP code.Privacy Guardrails: Never share billing API keys, database hashes, or internally marked ticket numbers with customers.Scope Boundaries: Any request or topic not covered by the manual must be escalated to human support rather than addressed with assumed policies.Repository StructurePlaintextprompt-engineering-support-assistant/

Key Design PrinciplesPolicy Grounding: All outputs derive strictly from the documented manual with zero outside assumptions.Empathy: Immediate emotional validation for angry or frustrated users without defensive phrasing.Privacy Protection: Never disclose billing API keys, database hashes, or internally marked ticket numbers.No Unsupported Claims: Frontline agents never promise actions or timeframes beyond authorized bounds.Self-Verification: Pre-delivery reflection checks prevent policy-breaching drafts from reaching customers.Controlled Escalation: Systematic routing of high-value disputes and out-of-scope issues to human teams.Structured CRM Output: Predictable, tabular data formats ensuring clean operations logging.ValidationThe prompting architecture has been validated through end-to-end execution against three distinct test scenarios:Account Verification: Successfully gated profile email changes behind mandatory Account ID and billing ZIP code verification.Refund Within Authority: Handled a high-friction double-charge complaint by offering an authorized $15 refund without unnecessary escalation.Refund Exceeding Authority: Correctly prevented unauthorized payout on a $120 annual plan refund request, routed the case to human management, and compiled an escalation handover ticket.DocumentationFor full implementation details, prompt templates, and execution records, refer to:Support Prompt LibraryConversations PortfolioChatbot DocumentationProject StatusThe prompt architecture design, pipeline verification, and scenario validation are complete.
